# 合并类别 B（13→7）+ 开集重跑 计划

## 核心结论：不需要改任何现有代码

`proto_openset.py` 对类别标签完全通用——`choose_unknown()` 只取 `sorted(set(categories))` 再随机抽 `--n-unknown` 个。所以只要交给它一个 `unsafe_category` 已重映射成 7 类的 `.npz`，再传 `--n-unknown 2`，就正好实现"从 7 个合并类里随机抽 2 个当未知"，**原脚本一行不动**。合并**完全在数据层**完成：只改 `unsafe_category` 字段，特征不变。

## 一、新建目录（在仓库根 `openset/` 下，与 `openset-proto/` 平级）

```
openset/                                  # 仓库根
├── openset-proto/                        # 不改动
│   └── proto_openset.py                  # 不改动
├── get-embedding/outputs/...             # 原特征（只读）
└── merge-b7/                             # 新增，本次实验全部产物
    ├── merge_taxonomy.py                 # 读原 npz → 写 7 类合并 npz 到 data/
    ├── run_merge_b7.py                   # 驱动器：循环 层 × seed × 方法，调 openset-proto/proto_openset.py
    ├── aggregate.py                      # 汇总各 run 的 metrics.json → 均值±std + 报告
    ├── data/                             # 合并后的 npz（约 35MB/层，写进 .gitignore）
    ├── outputs/                          # proto_openset.py 每次运行产物（写进 .gitignore）
    ├── .gitignore                        # 忽略 data/ 与 outputs/
    └── 合并B7_实验报告.md                 # 最终报告（aggregate 生成）
```

## 三、运行矩阵与命令

- 层：L24、L32（必须显式传 `--npz`，因为脚本自带默认路径 `get-embedding/outputs/MMSB_sd_typo_decoder[-1].npz` **已失效不存在**）
  - L24 → `get-embedding/outputs/20260924-203107/MMSB_sd_typo_decoder[24].npz`
  - L32 → `get-embedding/outputs/20260924-175155/MMSB_sd_typo_decoder[32].npz`
- seed：42、43、44、45、46（每次随机抽 2 个未知类）
- 方法：`cac`、`arpl`（脚本 `--method` 只能单方法或 all，所以**每种方法单独一次调用**）
- 合计 2 层 × 5 seed × 2 方法 = **20 次调用**，每次只训 1 个 torch 模型

单次调用等价于（在 `merge-b7/` 内执行）：

```bash
python ../openset-proto/proto_openset.py \
  --npz data/MMSB_sd_typo_mergeB7_layer32.npz \
  --method cac --n-unknown 2 --seed 42 --device gpu0 \
  --output-dir outputs --run-name b7_L32_s42_cac
```

（`--run-name` 让目录名可预测、便于 aggregate 定位；时间戳前缀仍保留，不会覆盖任何旧结果。其余超参全部沿用上次实验默认值：`--split-mode group`、`--target-tpr 0.95`、`--dim 256` 等。`--device` 默认 `gpu0`，可改。）

## 四、汇总与报告

`aggregate.py` 扫 `merge-b7/outputs/*_b7_L{24,32}_s{42..46}_{cac,arpl}/` 下的 `*.metrics.json`，产出：

1. 主表（口径 B_matched）：行 = 层×方法，列 = AUROC / 闭集ACC / 未知拒绝率 / FPR@TPR95，取 **5 seed 均值±std**；A_full 作附表。
2. **每个 seed 抽中的未知类组合表**（读 metrics 里的 `unknown_classes`）——不同 seed 抽到的组合不同，必须并列展示，否则均值没意义。
3. 各合并类的**误判方向表**（沿用脚本自带的 attribution 输出）。
4. 写入 `merge-b7/合并B7_实验报告.md` 与 `merge-b7/aggregate_summary.json`。

## 五、报告里要写明的注意事项（避免与旧结果误比）

- 类别数从 13 变 7，**旧 13 类数字不可直接比**，只能定性对比（按你的选择，不另跑 13 类对照）。
- 方差主要来自"抽中哪 2 个未知类"，且合并后类大小很不均（465/443 vs 109），单 seed 波动会明显。
- 已知测试集规模随抽法变化，5 个已知类时测试集约 80~170 条，指标粒度较粗。
- 脚本日志里那条"灰区类 10-13"提示对合并后的类名不再生效（仅提示，无影响）。

- 不跑 13 类同协议对照。
